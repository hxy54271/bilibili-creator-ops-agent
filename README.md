# B 站创作者运营 · 进线打标 & 总结 Agent 原型（vibe coding）

> 为投递「产品经理实习生（创作服务 AI 提效方向）」而用 **vibe coding** 快速搭建的实战项目。
> 目标：把岗位 JD 里的抽象要求，落成一个能跑、能演示、能讲清楚的 AI 提效方案。

---

## 二、技术栈与运行

- 前端：**HTML + 原生 JS**，零依赖、零构建。
- 知识库与评测集：`data.js`；前端核心逻辑：`app.js`；界面：`index.html`。
- 大模型代理（RAG 升级）：`server.js`（Node 内置 `http` + `fetch`，零三方依赖）。

### 模式 A：规则基线（零依赖，双击即用）
直接**双击 `index.html`** 用浏览器打开即可（无需服务器、无需联网、无需 API Key）。
分类采用「关键词打分 + FAQ 检索召回加权」的确定性基线。

### 模式 B：RAG Agent（智能模式，需启动本地服务）
```bash
# 1) 配置大模型（任选其一）
#   方式一：环境变量
export LLM_PROVIDER=deepseek        # openai / deepseek / qwen / zhipu / custom
export LLM_API_KEY=sk-xxxx
export LLM_MODEL=deepseek-chat      # 留空则用 provider 预设默认值
#   方式二：复制模板后填 key（已被 .gitignore 忽略，不会提交）
cp config.example.json config.json

# 2) 启动服务
node server.js
# 3) 浏览器打开 http://localhost:3000
```
启动后，前端「运行模式」切到 **RAG Agent（智能模式）**：先对知识库做稀疏检索召回（标签体系 / FAQ / 维护口径），
再把检索到的知识切片作为上下文送入大模型，生成 **打标 + 结构化总结 + 分类依据**。
未配置 Key 时，`/api/rag` 自动走**演示模式（模拟大模型）**，可离线演示完整 RAG 流程；配置 Key 后无缝切换为真实大模型调用。

> 安全说明：API Key 仅存在于服务端（`config.json` / 环境变量），绝不进入前端代码或仓库。

### 评测逻辑可在 Node 下复跑
```bash
node -e "global.DATA=require('./data.js');const a=require('./app.js');
console.log('GoldenSet', a.runGoldenSet());
console.log('Routing ', a.runRoutingConsistency());"
```

## 三、功能一览

1. **知识库面板**：进线标签体系 + 维护口径可视化。
2. **进线打标 + 总结（双模式）**：
   - 规则基线：预测标签、置信度、FAQ 检索命中、结构化总结（用户类型/核心诉求/情绪/优先级/建议动作）。
   - RAG Agent：在基线之上，展示**检索召回的知识切片**与**大模型的分类依据**，体现 RAG 链路。
3. **Badcase 闭环**：对误判样本标记人工正确标签 → 自动生成「知识库迭代建议」，并持久化（localStorage）形成闭环。
4. **Golden Set 评测**：一键批量评测，输出 Top-1 准确率、Top-2 召回率与逐条明细。
5. **跨业务场景路由一致性专项评测（新增）**：一键评测同一业务诉求在不同场景/视角/表述下的路由稳定性，输出一致率与逐组明细。

### 当前评测基线
- **Golden Set**：17 条样本，Top-1 准确率 **88.2%**，Top-2 召回 **100%**（含 2 条对抗性样本，用于演示 Badcase 闭环）。
- **跨业务场景路由一致性**：7 组 × 多场景表述，基线路由一致率 **100%**（7/7）。
  - 注：知识库中「分成」同时命中「签约」与「收益」标签，是已知的口径歧义点；生产中需用语义消歧 / 字段标准化治理——本项目已将其列为知识库治理待办。

## 五、面试话术（怎么讲这段经历）

1. **为什么做**：我看到 B 站创作者运营在 CRM 里大量重复「进线分类 + 总结」，人工效率低、口径不统一，于是用 AI 工具快速搭了个原型验证可行性。
2. **怎么做的**：先建结构化知识库（标签体系/FAQ/维护口径），再用「规则 + 检索」做基线 Agent，用 Golden Set 量化效果、用 Badcase 闭环持续纠偏——对应 JD 里知识库治理和 Agent 评测那套方法论。
3. **RAG 升级**：为了让 Agent 真正理解复杂进线，我加了一层稀疏检索召回知识切片，再交给大模型生成打标与总结，用 Node 做了个零依赖的本地代理，Key 只在服务端；这正好对应你说的「AI 提效方案落地」。
4. **路由一致性**：JD 明确要「跨业务场景路由一致性」，我专门做了分组评测——同一诉求换不同说法/视角都要稳定路由到同一标签，基线 100%；过程中还发现「分成」在签约和收益标签间的歧义，定位成知识库治理项。
5. **结果/认知**：基线 88% 说明规则基线可用，但生产要上大模型 RAG + 微调分类头；我特意放了 2 条对抗样本，说明我知道「Badcase 闭环」比一次性准确率更重要。
6. **体现的能力**：AI 工具落地能力（vibe coding）、把业务痛点翻译成方案、用评测集量化效果的产品 Sense。
7. **诚实边界**（被追问时）：真实大模型调用需要你自己的 API Key（仓库已留好配置位）；离线演示用的是标注清晰的模拟模式，绝不假装跑过真实模型。
